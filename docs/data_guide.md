# Data Guide: customer_churn.csv (synthetic)

Generated by `scripts/generate_data.py` (seed 42). 5,025 rows, 18 columns; one row per customer. **All data is fabricated**; no real customers.

**Decision question:** which customers should the retention team contact first, and with what action?

| Field | Meaning |
|---|---|
| customer_id | Unique ID (C100000+) |
| signup_date, tenure_months | Account start and age at 2026-09-30 snapshot |
| plan | Basic / Pro / Enterprise |
| contract | Monthly or Annual |
| payment_method, region | Card / Invoice / Bank transfer; sales region |
| seats | Licensed seats |
| monthly_charge | Monthly price in USD (some discounted) |
| logins_last_30d, logins_prev_30d | Logins in the latest and prior 30-day windows |
| features_used | Distinct product features used (0-15) |
| support_tickets_90d, avg_ticket_resolution_days | Support load; resolution blank when no tickets |
| late_payments_6m | Late invoices in 6 months |
| days_since_last_login | Recency of activity |
| nps_score | 0-10 survey score, blank if no response (~35%) |
| churned | Target: 1 = cancelled, 0 = retained |

## Planted data-quality issues (and how the notebook handles them)
| Issue | Count | Treatment |
|---|---|---|
| Exact duplicate rows | 25 | Dropped |
| logins_last_30d = -1 (invalid) | 6 | Rows dropped |
| Extreme seats values | 5 planted (49 capped) | Capped at 99th percentile |
| monthly_charge missing | 40 | Filled with plan median |
| nps_score missing | ~35% | Kept missing; adds 0 risk points, never imputed |
| ticket resolution missing | no tickets | Set to 0 |

## Quality rules
1. `customer_id` must be unique after cleaning (asserted).
2. Activity counts cannot be negative.
3. Churn rate before and after cleaning should match closely (24.1% both).
